# MovieLauncher

Собственный лаунчер под D-pad.

**В публичной сборке это домашний экран по умолчанию**
(`H96_HOME_LAUNCHER` в `device/h96proplus/device.mk`). У сопровождающего он был
лишь запасным вариантом: сначала использовался стоковый Google LeanbackLauncher
(проприетарный), затем сторонний Monet-Launcher (без лицензии) — ни один из них
распространять нельзя.

**Статус: собирается, APK получен, воспроизводимость сборки проверена.**
Версия 0.1, написана и собрана 2026-08-16 — до подключения устройства.
**На железе не проверялась** — см. чек-лист в конце.

- сетка плиток из установленных приложений, шесть колонок;

## Решения и почему именно так

### Никакого Leanback, Compose и Glide

ТЗ §33 прямо требует: быстрый старт, без тяжёлых animation-фреймворков, без
WebView, без загрузки из сети. Отсюда:

| Не используется | Почему |
|---|---|
| `androidx.leanback` | нужна ровно сетка с фокусом, а библиотека тянет заметно больше |
| Jetpack Compose | старт медленнее, выигрыша для сетки плиток нет |
| Glide / Coil | иконки отдаёт `PackageManager` из системного кэша, сеть не нужна |
| ViewBinding | лишний слой генерации; `findViewById` здесь достаточно |

Зависимости: `core-ktx`, `appcompat`, `recyclerview`. Всё.

Результат — 649 КиБ в release. Для сравнения, `LeanbackLauncher` из стоковой
прошивки весит 5,7 МиБ.

### DiffUtil вместо notifyDataSetChanged

`notifyDataSetChanged` сбрасывает фокус, и пульт «теряет» текущую плитку.
На телевизоре это сразу заметно и раздражает. `DiffUtil` обновляет точечно
и фокус сохраняет.

### Разрешений не запрашиваем

Ни `INTERNET`, ни доступа к хранилищу, ни `QUERY_ALL_PACKAGES`. Для списка
приложений хватает блока `<queries>` в манифесте. Чем меньше разрешений,
тем меньше поводов у системы будить процесс.

### «Назад» перехватывается

Лаунчер — это HOME, уходить некуда. Без перехвата случайное нажатие показывает
пустой экран.

## Сборка

```bash
export ANDROID_HOME=/path/to/android-sdk        # ваш Android SDK
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
echo "sdk.dir=$ANDROID_HOME" > local.properties

./gradlew assembleRelease

# вход для сборки образа (device/h96proplus/prebuilt-apps/Android.bp):
cp app/build/outputs/apk/release/app-release-unsigned.apk \
   ../device/h96proplus/prebuilt-apps/MovieLauncher.apk
```

Окружение (проверено сопровождающим): Android SDK 35 + build-tools 35.0.0,
JDK 21, Gradle 8.11.1, AGP 8.7.2, Kotlin 2.0.21.

⚠️ Собирать **на ext4**, а не на `/mnt/c`: Gradle на смонтированном
NTFS-разделе работает мучительно медленно и спотыкается на правах —
скопируйте проект в каталог файловой системы Linux.

⚠️ Нужен именно **JDK**, а не JRE: с `openjdk-21-jre` сборка падает на
`Toolchain ... does not provide the required capabilities: [JAVA_COMPILER]`.

## Подпись

Release собран **без подписи** — при сборке образа AOSP выравнивает его и
подписывает ключом сборки вместе со всей системой (в сборке разработчика это
публичные test-keys AOSP). Для отдельной установки на устройство
понадобится подписать самостоятельно:

```bash
apksigner sign --ks debug.keystore --out signed.apk app-release-unsigned.apk
```
