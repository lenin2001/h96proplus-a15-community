# Пульт управления

Заготовки для Milestone 8 (ТЗ §22–23), составленные **из стоковой прошивки**,
а не подобранные экспериментально.

```text
h96proplus-nec.toml           карта ИК-кодов для ядра (RC-core / ir-keytable)
Vendor_0001_Product_0001.kl   раскладка для Android
```

---

## Откуда взяты коды

Файл `/system/etc/remote.conf` установленной прошивки Франкенштейн содержит
полную заводскую таблицу штатного пульта:

```text
factory_code  = 0x40400001     custom code 0x4040, индекс 0001
work_mode     = 0              software mode
repeat_enable = 1              повтор при удержании
repeat_delay  = 130 мс         repeat_period = 120 мс
release_delay = 20 мс
```

и 35 кнопок со скан-кодами. Скопирован в
`H:\h96proplus-a15\vendor-blobs\remote\` вместе со стоковыми `.kl`-файлами.

Это избавляет от самой муторной части работы с пультом — подбора кодов
вслепую через `ir-keytable -t`.

---

## Как устроена цепочка

```text
ИК-приёмник → meson-ir → RC-core → keymap (.toml) → код ядра
                                                        ↓
                                        Android: .kl → событие системы
```

Два файла нужны в разных местах, и оба обязательны: без keymap ядро не
поймёт пульт, без `.kl` Android не поймёт ядро.

```text
h96proplus-nec.toml         → /lib/udev/rc_keymaps/  (или ir-keytable -w)
Vendor_0001_Product_0001.kl → /vendor/usr/keylayout/
```

---

## ⚠️ Что обязательно проверить на M8

### 1. Полный scancode

В `.toml` принято `0x4040<код>` — обычная схема для расширенного NEC при
custom code 0x4040. Реальные значения покажет:

```bash
ir-keytable -t          # нажимать кнопки и смотреть, что приходит
```

Если старшие биты окажутся другими, поправить их разом по всему файлу —
сами коды кнопок при этом не меняются.

### 2. Имя устройства ввода

Имя `.kl`-файла должно совпадать с тем, как система назвала устройство:

```bash
cat /proc/bus/input/devices
getevent -l
```

Если не совпадёт — просто переименовать файл.

### 3. Кнопки с неочевидным назначением

У vendor часть кнопок описана словами («KODI», «ALLAPP», «PROG_YELLOW»), но
назначенные им коды в Linux означают другое. Им подобраны ближайшие по
смыслу стандартные коды, и это надо проверить нажатием.

### 4. Пробуждение по IR — отдельный вопрос

ТЗ §23 требует, чтобы пульт будил устройство после сна. В `.kl` для POWER и
HOME стоит флаг `WAKE`, но этого мало: нужна поддержка драйвера и настройка
wakeup-источника в device tree.

```bash
cat /sys/kernel/debug/wakeup_sources | grep -i ir
```

На mainline это работает не всегда. Если не заработает — отдельная задача,
остальную функциональность пульта она не блокирует.

---

## Если штатный пульт не заведётся

Запасные варианты, оба в ТЗ §22 и так требуются:

```text
USB HID пульт   работает без настройки, Android распознаёт как клавиатуру
Bluetooth пульт зависит от M7
```

Устройство при этом остаётся управляемым, так что провал по ИК не
блокирует проект.
# Профиль 2026-09-06: RAW NEC + h96mouse

Активная карта Android — `h96-remote.map`: измеренный пульт с адресом 0x01,
кнопка мыши `0x100 -> KEY_F13 (183)`. TOML ниже — старый справочник другой
партии, он не используется службой `h96-irkeymap`.

`h96mouse` входит в PRODUCT_PACKAGES, создаёт `h96-remote` и
`h96-remote-mouse`. Первая кнопка мыши включает режим, вторая выключает.
Стрелки перемещают курсор, OK нажимает/отпускает левую кнопку. BACK, HOME,
громкость и POWER остаются клавишами, режим мыши не выключают.

Обязательно: RAW `amlogic,meson-gxbb-ir`, `CONFIG_INPUT_UINPUT=y`,
карта с KEY_F13 и патч framework 0012. В HW-ветке ядра 0012/0019 перехватывают
кнопки раньше userspace, поэтому два обработчика одновременно использовать нельзя.
Холодное включение после poweroff обслуживает загрузчик/SCP, а не этот демон.
