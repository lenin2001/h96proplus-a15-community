# kernel

Ядро — Linux v7.1 (stable, коммит `8cd9520d35a6c38db6567e97dd93b1f11f185dc6`)
плюс ряд из [`patches/series.json`](patches/series.json). Само дерево Linux
сюда не входит. Сборка — [DEVELOPMENT.md](../DEVELOPMENT.md#сборка-ядра-проверено).

## Что проверено (10.10.2026, по сборочному диску сопровождающего, только чтение)

- Шаги 1–3 ряда (HEVC + `0001-vdec-deferred-drain`) дают дерево, у которого
  git-хэши всех затронутых далее файлов совпадают с базой сборки #77;
  шаг 4 (снимок #77) — тоже до байта.
- После всех 26 шагов (`build/prepare-kernel.sh`) все 30 исходных файлов,
  которые меняет ряд, побайтно совпадают с деревом сборки **#112** (последней
  рабочей); сверка по SHA-256 из записи сборки `boot111r`.
- `config/h96proplus_defconfig` — `savedefconfig` полного `.config` #112;
  `make ARCH=arm64 h96proplus_defconfig` восстанавливает этот `.config` до байта.
- `../dt/meson-gxm-h96proplus.dts` — DTS дерева #112; DTB из него побайтно
  равен установленному на приставку.
- `build/build-kernel.sh` собирает `Image`, `Image.gz` и DTB в новом каталоге
  (aarch64-linux-gnu-gcc 13.3.0, без предупреждений). Сам `Image` с установленным
  побайтно не совпадёт: в строке версии — пользователь, хост и время сборки.

Номера сборок (#77…#113) и соответствие им шагов ряда — в `series.json`
(`builds`); патчи, которые не вошли, — с причиной в `not_applied`.

## Чего нет

- Загрузки на приставку ядра, собранного по этому рецепту: проверено
  совпадение исходников, а не работа нового образа.
- Модулей в образе: конфигурация включает поддержку модулей и около 1300
  драйверов `=m`, но образ их не содержит — работает только встроенное (`=y`).
  Всё, что нужно приставке, должно быть `=y`.
